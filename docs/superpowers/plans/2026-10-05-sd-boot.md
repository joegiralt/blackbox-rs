# SD-card Install Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** blackbox-rs examples build to a `BLACKBOX.bin` that 1010music's stock installer installs from the SD card, with stock restorable afterwards.

**Architecture:** One memory layout at `0x08040000` (no way to link lower). An assembly `__pre_init` plus a Rust cleanup routine return the CPU to a known state behind the installer. A Python check gates every image; a Unicorn test runs the real image from its reset vector with dirty CPU state. LEDs make every failure visible without a probe.

**Tech Stack:** Rust (thumbv7em-none-eabihf), embassy-stm32 0.6, cortex-m-rt 0.7.5, cargo-binutils, just, Python 3 + unicorn 2.1.

**Spec:** `docs/superpowers/specs/2026-10-05-sd-boot-design.md`

## Global Constraints

- Nothing links, flashes or writes below `0x08040000`. `FLASH ORIGIN = 0x08040000`, `LENGTH = 768K`.
- No image may contain code from `embassy_stm32::flash`.
- No 1010music firmware, patched images, installer dumps or disassembly listings are committed. `out/` and `.venv/` are git-ignored.
- Match the crate's existing style (module docs, comment density, `defmt` logging).
- Every `unsafe` block carries a `// SAFETY:` comment.
- Commits: terse subject, no type prefix, no AI attribution lines.
- Nothing is pushed, forked or opened upstream; local commits on branch `sd-boot` only.
- Task 7 touches the owner's hardware and is run by the owner, never by an agent.

## Review Focus

1. Installer jumps on the process stack, unprivileged, or with interrupts masked → image must still reach `main` on MSP, privileged, interrupts enabled. (Task 3 test)
2. A HardFault, not a panic → LEDs must blink, not a silent halt. (Task 4 test)
3. A downstream crate brings its own `memory.x` at `0x08000000` → `just sd` must refuse the image. (Task 1 test, Task 6 README warning)
4. A debug-profile or oversized image → refused before it reaches a card. (Task 1 test)
5. RTT log buffer fills with no probe attached → app must keep running. (Task 7, step 5 soak)

**Interfaces:**

### Task 3: Start clean behind the installer

**Files:**

**Interfaces:**

- Produces: link symbol `__pre_init` (assembly) and `__behind_installer` (`unsafe extern "C" fn()`), both in `src/boot.rs`. `just test` runs `python3 tools/test_check_image.py`, then `just sd demo`, then `.venv/bin/python tools/test_boot.py demo`.

- [ ] **Step 1: Write the failing test** `tools/test_boot.py <example>`. Set up `.venv` with `python3 -m venv .venv && .venv/bin/pip install unicorn==2.1.4`. The harness (this shape is proven to reach `main` on this crate):

```python
uc = Uc(UC_ARCH_ARM, UC_MODE_THUMB | UC_MODE_MCLASS)
uc.ctl_set_cpu_model(UC_CPU_ARM_CORTEX_M7)
uc.mem_map(0x08000000, 0x200000); uc.mem_write(0x08040000, image)
uc.mem_map(0x24000000, 0x80000);  uc.mem_map(0x20000000, 0x20000)
uc.mem_map(0xE000E000, 0x1000)    # SCS as plain RAM
uc.mem_map(0x58024000, 0x1000)    # RCC as plain RAM
```

Dirty state before the run: `MSP = 0x20001000`, `PSP = 0x20002000`, `CONTROL = 2`, `PRIMASK = 1`; memory `SysTick CSR (0xE000E010) = 7`, `MPU CTRL (0xE000ED94) = 5`, `CCR (0xE000ED14) = 0x00030200`, `CCSIDR (0xE000ED80) = 0xF003E019`. Record every memory write with a `UC_HOOK_MEM_WRITE` hook. Run from the reset vector (`image[4:8] | 1`) until the ELF symbol `main`, `count=20_000_000`.

Assertions on arrival:

```python
assert pc == sym["main"]
assert uc.reg_read(UC_ARM_REG_CONTROL) & 3 == 0
assert uc.reg_read(UC_ARM_REG_PRIMASK) == 0
assert uc.reg_read(UC_ARM_REG_SP) > 0x24000000            # on our stack, not the installer's
assert mem32(0xE000ED08) == 0x08040000                     # VTOR
assert mem32(0xE000E010) == 0                              # SysTick stopped
assert (0xE000ED04, 1 << 25) in writes                     # PENDSTCLR
for n in range(8):
    assert (0xE000E180 + 4 * n, 0xFFFFFFFF) in writes      # NVIC ICER
    assert (0xE000E280 + 4 * n, 0xFFFFFFFF) in writes      # NVIC ICPR
assert mem32(0xE000ED94) == 0                              # MPU off
assert [v for a, v in writes if a == 0xE000ED98] == list(range(16))   # RNR 0..15
assert mem32(0xE000ED14) & (1 << 16) == 0                  # D-cache off
rstr = [0x7C, 0x80, 0x84, 0x88, 0x8C, 0x90, 0x94, 0x98, 0x9C]
for off in rstr:
    vals = [v for a, v in writes if a == 0x58024400 + off]
    assert len(vals) >= 2 and vals[0] != 0 and vals[-1] == 0   # pulsed, released
```

- [ ] **Step 2: Run** `just sd demo && .venv/bin/python tools/test_boot.py demo` — expect failure at the `CONTROL` assertion.
- [ ] **Step 3: Implement `src/boot.rs`.** The entry is assembly because it changes the active stack:

```rust
// The installer may jump on its own process stack or unprivileged; the stock app's reset
// handler defends the same way. cortex-m-rt has already loaded MSP (`set-sp`).
core::arch::global_asm!(
    ".section .text.__pre_init",
    ".global __pre_init",
    ".thumb_func",
    "__pre_init:",
    "movs r0, #0",
    "msr CONTROL, r0",
    "isb",
    "b __behind_installer",
);
```

`#[no_mangle] unsafe extern "C" fn __behind_installer()` then does, in this order: SysTick `CSR = 0` and `ICSR = 1 << 25`; NVIC `ICER[0..8]` and `ICPR[0..8]` all-ones; MPU `CTRL = 0`, then `RNR = r`, `RBAR = 0`, `RASR = 0` for `r` in `0..16`; if `SCB::dcache_enabled()`, `disable_dcache`; pulse the nine RCC reset registers; `BASEPRI = 0`, `cpsie f`, `cpsie i`. Rules:

  - It runs before RAM is initialised: no statics, no `defmt`, no panicking paths. `cortex_m::Peripherals::steal()` is allowed (its one static write lands in `.bss`, which `Reset` zeroes afterwards) — say so in the `// SAFETY:` comment.
  - RCC resets go through `embassy_stm32::pac::RCC` (`ahb3rstr`, `ahb1rstr`, `ahb2rstr`, `ahb4rstr`, `apb3rstr`, `apb1lrstr`, `apb1hrstr`, `apb2rstr`, `apb4rstr`): set every reset field the PAC defines for that register, then write the register back to 0. Never write raw all-ones; reserved bits stay 0.

### Task 5: boot_probe, and a quiet demo

**Files:**
- Create: `examples/boot_probe.rs`
- Modify: `examples/demo.rs`

**Interfaces:**
- Consumes: `clock::config()`, `leds::Leds`, `mod fault`.
- Produces: example `boot_probe` — `embassy_stm32::init(clock::config())`, build `Leds` from the same 11 pins as `init()`, show the silicon revision for 3 s, then chase one LED at 100 ms per step forever. It touches no SDRAM, display, I2C, codec or SAI.

Revision is `DBGMCU IDC` (`0x5C00_1000`) bits 31:16: `0x1003` Y → LED 0; `0x2003` V → LED 1; `0x1001` Z → LED 2; `0x2001` X → LED 3; anything else → LEDs 0–3 together.
